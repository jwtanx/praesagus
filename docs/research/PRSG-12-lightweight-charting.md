## Recommendation

Start a bounded **TradingView Lightweight Charts** spike for a searchable ticker list and one selected instrument with price/volume panes. Prefer **Apache ECharts** if sector heatmaps and varied dashboard charts are the first deliverable. Consider **Highcharts Stock** if built-in indicators, accessibility tooling and vendor support justify its licensing dependency. These are the strongest three fits for the stated requirements, not a measured universal performance ranking.

The existing React 18/Vite 5/TypeScript frontend has no chart dependency ([package](../../frontend/package.json)); Dashboard currently prints chart-data JSON ([implementation](../../frontend/src/pages/Dashboard.tsx)). The Moomoo adapter supplies request-scoped latest quote snapshots and news search, not historical bars ([adapter](../../connectors/moomoo_opend.py)). A chart library supplies neither licensed US/MY history nor prediction quality. A quote snapshot cannot be converted into genuine OHLC candles.

## Comparable options

| Criterion | Lightweight Charts | Apache ECharts | Highcharts Stock |
|---|---|---|---|
| Financial series | Native line, area, OHLC bars, candlesticks, histogram volume; baseline series | Native candlesticks plus line/area and bar volume; standalone OHLC-bar style needs a custom-series investigation | Native OHLC/candlestick, line/area and volume columns |
| Indicators / overlays | Add computed line series; official indicator examples exist, calculations still need an owned method | Computed series/marking configuration; no complete finance indicator suite established in this scan | Documented built-in technical-indicator modules |
| Linked charts | Same-chart panes; crosshair/time-range subscriptions for separate charts | `connect` groups chart interactions; validate timeline alignment and feedback loops | Official synchronization example; shared extremes/crosshair wiring still needs integration |
| Other charts | Financial time series focus; histogram is not a general category-bar/heatmap system | Strongest fit for heatmaps, category bars and mixed dashboard views | Core chart types plus optional modules; check the licensed module set |
| React/Vite | Official React example; imperative instance inside effect/ref, cleanup on unmount | Tree-shakable ESM/TS; app-owned React ref/effect/resize/dispose adapter | Official React integration; confirm the chosen React wrapper supports Stock entry points |
| Runtime / bundle | Narrow financial surface; update last bar rather than replace all data | Import only chosen series/components/renderer; Canvas or SVG choice affects memory and workload | Stock, indicator and accessibility modules add functionality/cost; data grouping affects visible detail |
| Mobile / accessibility | Official accessibility plugin adds semantic layers/keyboard support; evaluate touch and screen reader behavior | Coarse-pointer option; ARIA/decal support requires explicit configuration; not equivalent to complete keyboard navigation | Accessibility module, descriptions and keyboard tooling; still requires application testing |
| License | Apache-2.0; required TradingView NOTICE attribution and public link | Apache-2.0; retain license/notice obligations | Stock license required for Stock features; commercial launch terms must be reviewed |

### Evidence supporting the table

- **Lightweight Charts:** [getting started](https://tradingview.github.io/lightweight-charts/docs) was labeled documentation version **5.2** at retrieval; it specifies series, client-side ES2020/TypeScript builds, updates and attribution. [License](https://raw.githubusercontent.com/tradingview/lightweight-charts/master/LICENSE); [panes](https://tradingview.github.io/lightweight-charts/tutorials/how_to/panes); [crosshair synchronization](https://tradingview.github.io/lightweight-charts/tutorials/how_to/set-crosshair-position); [React example](https://tradingview.github.io/lightweight-charts/tutorials/react/simple); [indicator examples](https://tradingview.github.io/lightweight-charts/tutorials/analysis-indicators). Financial specialization makes it the preferred MVP **inference**; no latency comparison was performed.
- **ECharts:** [selective imports](https://echarts.apache.org/handbook/en/basics/import/) and [Canvas/SVG guidance](https://echarts.apache.org/handbook/en/best-practices/canvas-vs-svg/) document renderer and bundle choices. [Maintainer API source](https://raw.githubusercontent.com/apache/echarts-doc/master/en/api/echarts.md) documents `connect`, coarse-pointer interaction and lifecycle. [Candlestick options](https://raw.githubusercontent.com/apache/echarts-doc/master/en/option/series/candlestick.md), [heatmap options](https://raw.githubusercontent.com/apache/echarts-doc/master/en/option/series/heatmap.md), [ARIA/decal guidance](https://echarts.apache.org/handbook/en/best-practices/aria/) and [license](https://raw.githubusercontent.com/apache/echarts/master/LICENSE) support its breadth. JS-only examples/API pages exposed little text, so maintainer documentation source was used. Documentation mixes `aria.show` and `aria.enabled`: verify against the pinned release rather than copying an old example.
- **Highcharts:** [Stock concepts](https://www.highcharts.com/docs/stock/understanding-highcharts-stock), [indicator modules](https://www.highcharts.com/docs/stock/technical-indicator-series), [React integration](https://www.highcharts.com/docs/react/getting-started), [accessibility](https://www.highcharts.com/docs/accessibility/accessibility-module), [synchronization example](https://www.highcharts.com/demo/highcharts/synchronized-charts) and [license FAQ](https://www.highcharts.com/docs/getting-started/frequently-asked-questions) support the feature-rich alternative. [Data grouping](https://www.highcharts.com/docs/stock/data-grouping) aggregates according to horizontal pixel density. [Boost](https://www.highcharts.com/docs/advanced-chart-features/boost-module) changes rendering/interactivity; documentation says it does not activate when Stock data grouping is enabled. Do not assume every financial series benefits from Boost.

All sources above were reviewed by the stated cutoff; exact individual request times were not instrumented. Links to `master` and current docs are mutable. Pin package versions and record the corresponding license/NOTICE before implementation. No precise gzip sizes, commercial fees, phone FPS or browser compatibility rankings are asserted: these depend on selected modules/build/device and remain unmeasured.

## Proposed MVP and data contract

Use one lazy-loaded selected-ticker chart, a searchable accessible list, 1M/3M/1Y ranges, line/candle switch, separate volume pane and one explicitly specified SMA overlay. Desktop places list beside chart; mobile stacks them. Provide touch controls, keyboard selection, visible currency/session/as-of/source, a textual summary and downloadable/table OHLC alternative. Render an explicit history-unavailable state for unsupported instruments. Keep general dashboard heatmaps out of the first chart ticket; adding ECharts later should have its own bundle justification.

Require: stable instrument + venue identifier, listing currency, ordered unique interval timestamps, source timezone/session calendar, open/high/low/close/volume, adjustment basis, corporate-action handling, publication/availability/retrieval times and entitlement/redistribution policy. Daily business dates are exchange session dates; UTC intraday timestamps map to a clearly labeled display zone. Never fabricate holiday bars, interpolate missing OHLC or mix adjusted close with raw other fields. Use sufficient pre-range bars for indicator warmup; null gaps stay visible. Vendor estimates, observed prices and forecast overlays must remain distinguishable.

Library adapters differ: Lightweight Charts uses named time/OHLC records; ECharts candlestick arrays default to open/close/low/high order; [Highcharts OHLC tuples](https://api.highcharts.com/highstock/series.ohlc.data) use timestamp/open/high/low/close. That API page identifies v13.1.0 generated 18 September 2026; this is an observed documentation version, not a pinned dependency. Canonical typed bars should isolate those mappings. Do not pass one positional representation to all three.

## Replayable performance experiment — proposed, not run

Engineer should pin versions and build identical Vite production routes with only required modules. Use an owned seeded generator with published seed/hash for 250, 2,500, 10,000 and 100,000 valid ordered bars; fixtures include a weekend/holiday gap, duplicate timestamp rejection and a split-adjustment case. Compare one instrument, two synchronized charts, price+volume+SMA, and ten visible sparklines; do not mount 50 detailed charts automatically.

Record compressed JS transfer separately from data bytes, cold/warm first usable chart, ticker-switch p50/p95, pan/zoom frame times, long tasks, peak memory where supported, and teardown after 100 mount/unmount cycles. Use fixed playback of latest-bar updates at 1 and 10 Hz with a logged sequence; throttle/coalesce background updates. Preserve identical data, visual complexity, browser/device versions and network conditions. Evaluate Canvas/SVG choices where available and expose aggregation to readers.

**Provisional acceptance targets**, requiring Lead agreement: cached 2,500-bar switch p95 under 300 ms; pan/zoom p95 frame time under 33 ms on a named midrange phone; first useful chart within 2 s under a specified mobile connection; no body overflow at 390 px; keyboard-only ticker/range navigation and understandable screen-reader data access. Repeat 20 switches per condition after five warmups; report distributions and failures, not only a best run. Run Chrome desktop, Android Chrome and iOS Safari on actual target devices. Package payload has no assumed threshold until first baseline measurement. This experiment was not implemented or executed during research.
