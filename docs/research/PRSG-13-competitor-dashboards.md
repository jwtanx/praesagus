# PRSG-13 — Competitor workflows and feature hypotheses

Research reviewed **1 October 2026, 18:44:18 MYT**, within the accepted three-hour evidence-gathering ceiling. Six official product/help sites were opened. Exact publication/update and individual retrieval times were mostly unavailable; the review cutoff is recorded, not represented as each page's publication time. This is a vendor-documentation scan, not logged-in usability testing, independent feature verification or market-demand validation. Lead decides priorities.

## Finding

The repeatable workflow is **discover → save/watch → inspect evidence → monitor changes**. Competitors emphasize reusable watchlists, screening, comparisons and alerts. Praesagus has useful source-linked financial records and dated reports, but neither comprehensive provider coverage nor an operating model-backed answer service. A smaller, auditable monitoring workspace is a better initial hypothesis than copying a broad terminal or launching unsupported stock ratings. This prioritization is an inference to test with users, not a proven advantage.

## Compare three strategic options

| Option | Why consider it | Main tradeoff | Conditional preference |
|---|---|---|---|
| Watchlist + evidence workspace | Koyfin/TIKR/Finviz show repeated saved-monitoring workflows; fits existing financial inputs | Persistence, deduplication and freshness must be reliable before alerts | Preferred MVP direction if user research confirms daily monitoring is the core job |
| Broad screener + market overview | TradingView/Finviz/Stock Analysis document discovery and comparison tools | Broad licensed universe, normalized fundamentals and screening quality substantially expand data obligations | Start with filterable known universe only if users struggle to select instruments |
| Ratings / valuation research terminal | TIKR/Seeking Alpha document fundamental models/ratings workflows | Method validation, estimate licensing and false precision risk; current Praesagus has no LLM answer runtime | Defer generated ratings until evidence and evaluation gates exist |

## Five ranked feature hypotheses — proposals, not accepted scope

Effort ranges below are rough person-day estimates for a single-host MVP with existing inputs, excluding data licensing/provisioning and uncertainty from deployment. They require Engineer review. Metrics are proposed experiment gates, not claimed results.

| Rank / hypothesis and user job | Smallest MVP | Why / dependencies and rights | Effort estimate | Measurable experiment |
|---|---|---|---|---|
| 1. Evidence-aware watchlist workspace: daily reader finds what changed for saved names | One shared editable list, saved filters and ticker drill-through to existing source records; visible list revision/as-of; no personalized portfolios | Repeated Koyfin/TIKR monitoring pattern; reuse PRSG-4 and existing catalyst API. Requires persistence/conflict policy, stable venue IDs and permitted source links/content | 3–6 days | Five representative readers locate a ticker's latest cited event and quote timestamp; at least 4/5 succeed unassisted, median under 60 s, zero stale quote mistaken for live |
| 2. Honest freshness/coverage dashboard: researcher knows what can be trusted | Instrument one financial ingestion path first; last attempt/success/source time, missing/stale/error state; expand after replay | Supports every workspace/chart/alert and current MY gaps; reuse PRSG-2. Needs run metadata and per-dataset freshness policy, not just file mtimes | 2–5 days first path | All injected failed/missing/stale/future cases visibly classified on next refresh; valid empty run distinguished; 4/5 readers explain the data limit |
| 3. Event-linked technical detail: reader checks price context around a sourced event | One selected ticker, licensed daily OHLCV, price/volume/SMA and linked calendar/news marker, visible provenance; explicit unsupported-history state | TradingView/Stock Analysis chart-to-research pattern; PRSG-12 shortlist. Depends on US/MY history rights, adjustment/session rules and evidence availability; markers are not causal proof | 3–6 days after data contract | Meet PRSG-12 device benchmark gates; 4/5 readers distinguish event time, quote time and conditional forecast; never show synthetic candles from snapshots |
| 4. Bounded catalyst notification inbox: reader gets material changes once | Persisted deduplicated alert outbox for one watchlist/event class, acknowledgement and one explicitly authorized delivery channel | Koyfin/Finviz/Seeking Alpha alerts; reuse PRSG-5. Needs scheduler/provider rights, quota/error controls, consent and delivery evidence; avoid continuous-push claims | 4–8 days | Replay 100 duplicate/changed/failure events: one intended alert per event revision, no future-evidence alert, visible retry/dead-letter state and measured notification noise |
| 5. Filing evidence / comparison card: analyst checks numbers against disclosure | One issuer's filing facts with period/unit/source extraction, linked original document, revision/missing state; compare two periods rather than rank all stocks | TIKR/Seeking Alpha fundamental-depth pattern; reuse PRSG-3. Requires normalized filing provenance, unit/currency validation and extraction review; MY disclosures need separate source contract | 4–7 days for one disclosure family | Twenty frozen facts manually reconciled to originals with zero unit/period mismatch; 4/5 readers recover original disclosure within 30 s; mark unsupported facts rather than estimate |

Ranks prioritize reuse and evidence quality, not estimated revenue. Freshness is a release prerequisite for observed-data claims in items 1/3/4 even though the user-facing workspace ranks first. The three most useful near-term experiments are workspace task success, freshness failure visibility and chart evidence comprehension. Alerts and fundamentals add value only if inputs and source rights support them. Portfolio allocation, broker sync, autonomous trading and generated buy/sell rankings are outside these MVPs.
