### Checkpoints and execution safety

For SetFit, [paraphrase-multilingual-MiniLM-L12-v2](https://huggingface.co/sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2) is Apache-2.0, revision `e8f8c211226b894fcb81acc59f3b34ba3efd5f42`; it is an embedding body, not a ready financial classifier. [Laya English](https://huggingface.co/convaiinnovations/laya) is Apache-2.0, revision `55cf4c4ebb4ebe31b2550e8bdf3bd21b99753851`. Revisions came from HF model API, not downloaded weight inspection; retain required notices and confirm every selected upstream dependency/checkpoint separately. English-first does not establish Malay/Chinese quality.

Do not load unknown serialized model files or enable remote model code by default. [scikit-learn persistence guidance](https://scikit-learn.org/stable/model_persistence.html) notes executable-code risks in pickle-based persistence and version compatibility limits. Later Engineer work should hash artifacts, record training/software versions and accept only reviewed local models. No generic model file can be declared safe from its extension alone.

## Minimal reusable data tooling

- Reuse existing requests/httpx/feedparser and financial schema conventions. Pydantic is already declared, but broad `>=1.10` plus old FastAPI warrants exact compatibility resolution; do not force a Pydantic 2 migration for this data pilot.
- Use [Python sqlite3](https://docs.python.org/3.11/library/sqlite3.html) for a private normalized store, parameterized queries, transactions and bounded single-writer handling. Store immutable raw JSON batches with hashes separately; corrections append revisions rather than overwriting originals. No public SQLite/database, broker credentials or raw restricted news on Pages.
- Use [zoneinfo](https://docs.python.org/3.11/library/zoneinfo.html) and versioned timezone data. Optional **[exchange-calendars 4.13.2](https://github.com/gerrymanoim/exchange_calendars/releases/tag/4.13.2)**, Apache-2.0, 670 stars, active Sep 24; Python ≥3.10, NumPy ≥1.26.4. Its [pinned registry](https://github.com/gerrymanoim/exchange_calendars/blob/4.13.2/exchange_calendars/calendar_utils.py) includes XKLS and XNYS, with XNAS aliased to XNYS. Reconcile against official exchange closures/half-days and recorded provider sessions; a shared alias is not proof of every venue's identical schedule. Package calendars can miss ad hoc holidays.
- Keep `harness/forecast_review.py` for existing frozen forecast validation/scoring. Do not introduce a new feature store, orchestration runtime, labeling platform or database server before the collection wedge is measured.

## Existing implementation gaps to preserve as visible limitations

Code inspection: `CompanyNewsConnector` uses Google RSS/SEC8-K, initializes absent publication time to retrieval time and only deduplicates links inside one fetch. Its name/docstring says earliest but does not establish earliest publication. The calendar connector repeats fixed month-day macro templates and estimates filing dates; these are not a verified current official schedule. Financial storage replaces current JSON records by source_id, trims to5,000 and returns empty on some load failures; it is not immutable training-history retention. These findings are implementation observations, not changes in this ticket. Avoid feeding substituted timestamps, lost revisions or silent empty data into evaluation.

## Proposed smallest Engineer boundary for Lead to freeze

1. Private batch collector for a small declared US/MY universe, completed regular daily bars and permitted primary news/disclosures. Before live collection, confirm account quota, two-market samples and rights; unsupported market remains visibly unsupported.
2. Immutable raw batches + SQLite instrument/session/bar-version/news-version/collection-run tables. Each row links raw hash, provider/code/venue/currency, request/retrieval/ingestion time, original publication/timezone, provider availability if known, first-observed time, adjustment/session basis and source/license status. Use explicit nulls for unknowns.
3. Capture **all eligible sessions**, ordinary/large moves, news-without-moves, no-observed-news, failures and non-trading sessions. A collection-run row distinguishes successfully empty responses from missed polls/outages. Freeze universe and sampling rules before selecting outcomes.
4. Validate finite OHLCV, completed bars, duplicate/revised batches, splits/dividends, session gaps and future timestamps; bounded retry/backoff and source-global quotas. Later deterministic fixtures cover malformed/stale/future/429/partial-page cases; no tests executed now.
5. Replay a mover explanation report with after-cutoff news explicitly explanation-only. Preserve causal ambiguity, sector/market controls and PRSG-24 labels. Later classifier evaluation uses chronological event grouping, calibration and untouched holdouts; no daily automatic skill retraining.

Lead decisions: approve this collection boundary, choose authorized provider/source contracts, resolve retention/public JSON rights and hardware; accept sklearn1.9.1 baseline and isolated SetFit experiment; decide whether Laya's young maturity merits optional resources. Stop on unresolved rights, insufficient MY evidence or missing point-in-time provenance. Numeric prediction and precise target prices remain a later separately validated experiment.
