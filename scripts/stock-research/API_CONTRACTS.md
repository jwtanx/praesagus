# Standalone stock-research collection contracts — PRSG-110 / PRSG-111

PRSG-110 supplies bounded injectable REST reads. Its separately released five-request capability pilot completed on 2026-10-15: 25 returned rows, 5.394 seconds, confirmed cleanup. It established a daily cumulative wrapper and observed raw timezone -4; it did not establish field currency, full calendar coverage, data rights, quotas or model quality. PRSG-111 adds selection and immutable collection, verified with fictional offline inputs only. No new live collection or metadata-endpoint run has been performed for PRSG-111. Training, inference, scoring and workbook delivery remain separate tickets.

## Implemented boundary

`ResearchProvider` requires injected API key, signer, transport, millisecond clock and nonce capabilities. Importing these modules performs no credential, Keychain or network access. `build_live_provider` calls the existing secure credential loader only when a caller explicitly selects an authorized live operation; its `allow_live` flag is a software input, not a permission system. The offline tests use fictional injected capabilities exclusively.

`ResearchReadTransport` inherits the existing TLS verification, fixed `webapi.moomoo.com:443` host, TLS 1.2 minimum, redirect rejection, identity-encoding and response-size checks, connection cleanup and request deadline behavior. Its separate allowlist permits only:

| Method | Endpoint | Wire/data boundary |
|---|---|---|
| POST | `/api/v1.0/quote/stock-screen` | US filter, explicit retrieve descriptors and sort, limit at most 300, opaque body `next_key`, `data.items`, top-level `pagination` |
| POST | `/api/v1.0/quote/stock-basicinfo` | 1–400 unique US codes, `data.basic_list`, missing/unrequested/duplicate identities checked |
| POST | `/api/v1.0/quote/snapshot` | 1–400 unique US codes, `data.snapshot_list`, observed prices/source time kept separate from completed bars |
| GET | `/api/v1.0/quote/US.<symbol>/history-kline` | Inclusive ISO start/end, daily `ktype=2`, `autype=0..2` (modeling default1), at most370 bars |
| GET | `/api/v1.0/quote/US.<symbol>/owner-plate` | Empty query/body; raw `data.sectors` INDUSTRY/CONCEPT/OTHER memberships, no broad-sector inference |
| GET | `/api/v1.0/quote/US.<symbol>/company/profile` | Empty query/body; raw `data.items` attribute IDs when supplied; absent IDs stay absent |
| GET | `/api/v1.0/quote/plate-list` | Exact `market=US&plate_class=INDUSTRY`; raw `data.plate_list`, empty list valid |

Account/order/news routes, arbitrary URLs, foreign market paths and arbitrary query keys are excluded. The old `SecureReadTransport` and reporting collector were not edited or widened. Signing preserves the sent body/query bytes: timestamp, uppercase method, path, raw query and SHA256 body digest joined by newlines, using the existing injected signer contract.

Requests are sequential within the provider; concurrent reads are rejected. Frozen local request, page, row and per-request timeout budgets bound work. The default request budget is 128; an explicit validated override may raise it to at most 2048. Full-universe multi-year bootstrap may therefore require incremental bounded runs and must report shortfalls rather than silently enlarge the default. A separately approved pilot can use a much smaller budget such as five requests. These numbers are **local safety limits, not verified REST quotas**. HTTP 429 stops the instance with a sanitized error and a bounded Retry-After hint; there is no automatic retry or sleep. Upstream bodies, credential/signature values and dependency exception messages are never copied into error text/context. Batch/request/provider reprs hide contents. Injected synchronous capabilities must honor their timeout; the wrapper cannot interrupt an uncooperative callable. The inherited transport's OS DNS/header trickle limitation remains; these checks do not certify an overall worker deadline or distributed quota coordination.

## Screening units, missingness and paging

The documented `simple_property_result` fixture is decoded only after matching the exact ordered query descriptor and typed `res`: result_type 1/dval, 2/ival (integer or documented decimal string), or 3/sval. Booleans, malformed numbers, missing typed values and mismatched descriptors are not coerced. Formatted `value` is never a numeric fallback. Documented simple-factor scaling is price 2201 /1000 and market cap 2301 /1000. Cumulative factors 3104/3105 and daily 3102 use their documented cumulative family; requesting them (or 3102) as simple fields is rejected. The reviewed turnover /1000 and volume raw units cannot be applied to an unestablished cumulative response wrapper. Unknown simple-factor units remain explicitly unavailable, including typed strings whose semantic factor is not established. REST tags are distinct from SDK/OpenD value_type.

Cumulative retrieve/sort requests support documented3104/3105 windows and daily3102 (`days=1,period_average=false`). The pilot established `cumulative_property_result` with `property`/`res`, integer period_average echo and result_type2/decimal-stringival. The decoder requires exact factor/day keys and integer0/1 echo strictly equal to the requested boolean encoding; response booleans, alternative integers, wrong days/factors and missing typed values reject or stay unavailable.3104 remains raw volume;3105 divides by1000. A period average is explicitly an average, never the required median. Non-daily/mean20 behavior has documentary/mock evidence rather than a live20-session validation.3102 retains raw evidence with unavailable numeric rate/base units, never an inferred ratio; final winner/loser ranks use comparable completed-bar returns. Unknown cumulative wrappers stay unavailable.

Only the reviewed US market filter is accepted initially; unsupported screening filters/descriptors fail explicitly. Query bytes remain frozen apart from opaque body next_key. Duplicate codes, repeated cursor, empty has_more page, oversized page, inconsistent total and terminal-cursor contradictions stop the operation. Reaching a page cap returns truncated status; terminal output shorter than reported total returns partial status, never a silently full universe.

## Canonical observations and history

Basic identity retains a validated stock_id exactly as returned (positive integer or decimal ID string); this internal provider security ID does not establish issuer or share-class grouping. Basic identity does not imply issuer strategy, signed leverage, sector or a fundamental data period. `stock_type=ETF` can include other funds/trusts/REITs; absent sector and fundamental-period provenance remain null. The three closed metadata routes above are the only enrichment additions; there is no automatic sector crosswalk or issuer resolver.

Snapshots retain source update milliseconds, actual data_date, retrieval/known time, raw numeric price/volume/turnover and validity flags. Missing fields stay null. Today low/high, when returned, remain live observations with their actual session date; they are not reclassified as completed model bars. Quote movement, screener match totals and local indicators never fill native UI bullish/bearish count columns.

History requires finite positive open/high/low/close with low <= open/close <= high, nonnegative integer raw volume and finite nonnegative turnover. Missing volume_precision is unverified units; volume is divided by 10**volume_precision. Prices/turnover use their documented ordinary units. Invalid/missing OHLC rejects the page. Duplicate dates/timestamps, invalid or future milliseconds and inconsistent raw offset/date arithmetic reject history. Raw date, time_key and integer time_zone are retained. Offset arithmetic uses the documented minutes contract with explicit time_zone_unit_status=documented-minutes/runtime-unverified and the documentation source URL; runtime units and provider bar finality remain unverified. Actual calendar/retrieval evidence does not establish those provider capabilities. A documented daylight example is not used to guess a timezone ID, and raw -4 is never silently converted to -240.

Each row carries adjustment mode, source, retrieval/first-known time and response-hash revision vintage. Currency stays null unless the caller supplies attributable `CurrencyEvidence` for that exact security, known by retrieval. The class validates its shape/cutoff, not the contents of the external source. `US.` alone never proves USD. Session completion requires a caller-supplied actual exchange-session close map; absent calendar evidence yields calendar-unverified. Coverage at least 252 requires the full required completed-session set, usable USD bars and known-time cutoff coverage; a raw row count cannot establish it. The provider wrapper supplies no exchange calendar. Collection uses exchange_calendars XNYS regular-session closes and records the dependency version and exact schedule hash; that calendar does not prove provider finality or point-in-time delistings/membership.

Three-year bootstrap can be requested with explicit start/end and bounded calendar-date windows (at most 180 days each), never an unbounded cursor walk. The next end is the oldest actual returned session date minus one day; an empty window advances to the requested left boundary minus one day. Strict backward progress and global date/timestamp uniqueness are required. A short/full page can be followed safely using actual dates, while missing sessions are rejected by calendar coverage checks rather than guessed. `next_time` is retained as raw milliseconds with unverified-not-used status; its relationship to the date-only end parameter is unresolved and it is never translated into a request end date. Repeated raw cursors cannot drive the loop. Page/request/row budget exhaustion remains visible, and missing sessions remain a coverage gap even after all bounded windows are visited. Current adjusted backfills and revision vintages do not prove historical point-in-time availability.

## Issuer registry and capability receipt

`etf_metadata.csv` contains49 unique issuer-attributed lookup rows:41 reviewed on2026-10-14 plus8 reviewed on2026-10-15. It is a **classification lookup only** for independently market-discovered names. It cannot seed candidates, fill quotas, establish a US listing, prove Moomoo entitlement/liquidity/history or fabricate historical mandates. `source_asof` is documentation observation date, not mandate effective date. Exact benchmark text and broader controlled exposure family remain separate; sharing a family does not establish an identical benchmark or independent diversification.

`classify_discovered_etfs` returns only supplied discovered codes, with selection eligibility and listing verification false until separate evidence establishes them. Unknown names remain unclassified. Ordinary real-estate ETF wrappers such as XLRE may be considered if independently discovered and eligible; individual REITs, ETNs and plain trusts are not ETF substitutes. Inverse/leveraged classification retains issuer daily reset and signed leverage; multi-day fund forecasts must use actual fund prices, not multiplied/reversed benchmark forecasts.

`ResearchProvider.capabilities()` reports native counts null/methodology-unverified, REST numeric quotas unknown, entitlements/live coverage unverified, reviewed daily cumulative wrapper/INT-flag echo, documentary/mock-only metadata endpoints and unverified next_time semantics. A successful mock demonstrates implementation handling, not current endpoint permissions, freshness, data rights, full calendar coverage, profitable selection or model quality. Only the explicitly scoped PRSG-110 operations have the limited live evidence noted above; new metadata/enrichment/whole-universe operations require a separately reviewed and released run.

## Current selection and reviewed input contract

`collect.py` performs US winners/losers/turnover discovery with three independent frozen query pools, then basic identity/snapshot/history collection. Registry, portfolio and report lists cannot seed these pools. Volume ranking uses latest_turnover/latest_volume and reference_session_date from the same valid completed bar; median20 is eligibility only. A bounded candidate/page/request budget may leave shortfalls. Past forecast names are fetched only for actuals, never inserted into current discovery. There is no forced rotation.

Core targets are20 winners,20 losers and40 latest completed-session dollar-turnover leaders plus20 ETFs (ordinary12, +2x2,+3x2,-1x2,-2x1,-3x1). Core eligibility requires completed calendar coverage of at least252 sessions, latest20 exact required sessions (not20 compressed rows), median turnover at least25M USD, completed reference close at least5USD, comparable reviewed price/volume/turnover basis and a source-verified listing/status. Unknown units are not filled from US prefixes, magnitude, price*volume or issuer listing currency. Current USD listing evidence for SPY alone does not establish REST history/turnover currency.

Stocks require a reviewed broad-sector crosswalk and attributable issuer/security relation. Quota-aware minimum-cost maximum-flow fills feasible slots before rank, with issuer cap1 inside allocation and sector cap16; it can choose an alternative share class to avoid a false quota shortfall. Same-issuer conflicting verified sectors are rejected rather than choosing the first. ETFs use issuer lookup classification and shared family cap2 across signed leverage buckets; allocation can reassign high-ranked geared candidates when required to fill inverse quotas. Exact benchmark identity remains separate from concentration family; no provider benchmark-symbol inference. A verified ETF wrapper with Trust in its name is not excluded by substring. A provider stock/registry ETF type conflict stays unresolved.

Up to10 speculative stocks remain disjoint from main names/known issuer groups: price at least1USD, latest20 median turnover at least5M, plus low-price/short-history/large-move/high-volatility flags. Unknown data never force-fills either list. Coverage separates source/budget truncation, missing units/history/identity, and exhausted eligible pools.

Optional reviewed JSON input has schema_version1 and sections listing_records, currency_evidence, comparison_evidence, issuer_relations and industry_evidence keyed by exact independently discovered US code, plus sector_crosswalk records. No default crosswalk/issuer aliases are supplied. Evidence requires source URL/hash, reviewer, verified status and cutoff-safe knowledge: all provided known/available/first-seen/retrieved/observed times are considered, using their maximum rather than an earlier asserted known_at alone. Explicit effective_from/to gates reject future/expired records; unknown intervals remain current-only. Date-only effective bounds use UTC days with inclusive end; explicit timestamp end is exclusive. ETF source_asof and precise observed_at, if present, must not be later than cutoff.

Currency requires exact code and typed stock_id binding, endpoint=history-kline, verified identity binding, explicit OHLC/turnover field scope and applicable session interval. Listing evidence cannot substitute. New evidence re-evaluates every cached row, preserving original price known time and assigning enriched availability no earlier than source evidence or this collection's own enrichment receipt. Expired/missing evidence clears currency eligibility in a new vintage; old generations remain intact. Comparison evidence supplies reviewed USD price/turnover, share-volume and adjustment basis; it is not an automatic provider factor certificate. Current financial metrics and classifications never become historical training features.

Industry inputs retain exact taxonomy ID/snapshot hash, source industry code/name/type and profile label separately. Mapping requires an exact reviewed versioned crosswalk; CONCEPT/OTHER, missing mappings, conflicting memberships/profile labels or unknown versions cannot prove a broad sector. Issuer IDs/namespaces/group relations are attributable inputs; security ISIN, display-name/site equality or punctuation cannot prove shared issuer.

Optional enrichment retains raw source industry/profile/catalog observations without auto-approving a mapping. Profile stock attributes7/8/9/14/15/23/50 remain source-coded symbol/ISIN/name/exchange/market/site/industry; tags without those IDs stay raw. Snapshot equity metrics require equity_valid=true; finite negative EPS/profit/PE remain signed. EPS/profit are labeled previous fiscal year with unknown year-end, trailing metrics retain documentary period, monetary currency remains unverified. These are current display context, never profitability guarantees or training features.

## Immutable state and downstream dataset interface

Default parent is `~/Documents/stock-research-data`. Each generation uses one MYT timestamp for exclusive `YYYY-MM-DD_HHMMSS` folder creation (0700) and manifest. Files are exclusive0600 writes. Collisions reject; no fixed latest/cache/model is overwritten. In-repository output needs an entirely ignored data parent outside root/code paths, otherwise a clear setup error is returned. No .gitignore changes are supplied by this ticket.

Collection manifest: schema_version1, kind=stock-research-collection, canonical_history_schema_version1, generated_at, as_of_ms and compatibility_id (state/history schema, adjustment mode, calendar and policy version), plus root-relative artifact path/SHA256/byte count. Readers validate all referenced files before choosing latest compatible state; incomplete generations and kind=capability-pilot are not collection state. Model/prediction manifests are separate; there is no model loading/training here.

Artifacts:

- `history.csv`: latest cached row per exact(code,session_date); columns are authoritative in `storage.HISTORY_COLUMNS`. OHLC/volume/turnover are numeric; null currency stays blank. Source/source_at_ms, raw date/time/time_zone, runtime-unit/provider-finality status, retrieved_at_ms, known_at_ms and response revision_vintage remain distinct. Additional price_known_at_ms, currency_known_at_ms, currency_evidence_hash and currency_status separate price availability from later unit admission. Completed is a boolean CSV field; it reflects calendar/retrieval evidence, not a provider finality guarantee.
- `history_revisions.csv`: new/revised/reobserved rows, old/new row hashes and availability/vintage. Unchanged observations retain first-known time. Conflicting values at the same exact code/session/known timestamp reject instead of input-last-wins. Old folders remain available for AI Engineer's later as-of reader; latest_state is only the current revision view. Offline replay without an explicit replacement metadata input reuses the previous hash-verified metadata_input.json and still applies expiry at the new cutoff; an explicitly supplied empty input withdraws evidence.
- `state.json`: current pool ranks/records, public security identities/snapshots, raw current-only metadata, membership first-seen times, history status and reviewed adjustment-vintage IDs; history rows are referenced via the manifest CSV rather than duplicated here.
- `identity_bindings.json`: exact code/stock_id plus source/hash/retrieved/known and null effective intervals; current-observation binding is not a historical ticker/issuer alias claim. A fresh stock_id change for the same exact code clears that symbol from the active cached basis and requests new history; old folders persist. Identity quarantine blocks selection/scoring until a new exact reviewed listing/history binding is verified at or after the transition. New history is never blended with the old security merely because its ticker matches.
- `calendar.json`: actual completed session/UTC close list, calendar dependency/version and schedule hash; manifest repeats the hash/version.
- `metadata_input.json`: exact reviewed input receipt for replay; `universe.json`, `universe.csv`, `speculative.csv`, `coverage.json`: selection, reasons/ranks, diagnostics and honest shortfalls. These are not forecast/workbook exports.

Canonical OHLC is forward split-adjusted excluding distributions by default (autype1); raw mode remains explicit. Response hashes are not adjustment factors. A changed reviewed adjustment_vintage_id requests fresh full backfill and invalidates that symbol's current cached basis without deleting prior folders. Missing factor evidence is declared; cross-window/volume adjustment equivalence and fully point-in-time history are never inferred. First collect backfills are retrospective and membership begins at actually observed discovery, not historical bar dates. Budget-truncated histories resume missing older ranges before recent revision refresh; already retrieved partial pages are retained on a bounded failure and network work stops.

Future prediction manifests schema1/kind=stock-research-prediction declare pending_forecast_symbols, or forecast_symbols when pending is absent. Collection retains these names for actuals after they leave discovery, without changing original forecasts. No scoring, SQLite writer, benchmark seed list or historical leverage guesses are supplied. Benchmark inputs need a separately declared mapping in the dataset stage.

## Manual configuration and test boundary

It never loads credentials/providers. Normal manual online invocation requires an explicit private0600 locator reference outside the repository, set by collection.credential_locator_file or PRSG_MOOMOO_CREDENTIAL_LOCATOR; it has no baked actual directory/AppKey name. The existing secure loader validates the referenced credential directory/key when an approved online run actually executes. No credentials or locator values belong in repository configuration.
