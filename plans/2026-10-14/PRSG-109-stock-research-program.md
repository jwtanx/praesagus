# PRSG-109 — Standalone Moomoo Stock and ETF Research Scripts

## 1. Goal and agreed scope

Build an on-demand Python tool under `scripts/stock-research/` that discovers liquid US instruments, collects Moomoo data, trains a small numerical model locally, and exports price forecasts and sortable research candidates.

Save this program plan under `plans/2026-10-14/PRSG-109-stock-research-program.md`, with its matching manifest. This is the user-approved implementation specification. The human explicitly requested publishing the plan before implementation. Existing tickets and reporting work are set aside.

The agreed scope is:

| Item | Decision |
|---|---|
| Main universe | Target 100 unique instruments: 80 company stocks and 20 ETFs |
| ETFs | Include ordinary long, inverse, and 2x/3x leveraged products |
| Discovery | Market-wide winners, losers and volume/liquidity rankings |
| Speculative stocks | Separate panel of up to 10; excluded from the main 100 and top 20 |
| Forecast inputs | Completed regular-session daily bars |
| Forecast windows | Next 1, 3 and 5 trading sessions; next calendar week |
| Predicted prices | Lowest low and highest high across each whole window |
| Actions | Long-only research screening: BUY candidate, SELL/avoid, WATCH, NO TRADE |
| LLM | Optional news-to-number sentiment; on (skip sentiment-to-number analysis if the LLM connection check fails) by default     |
| Outputs | CSV datasets plus a formatted workbook with tabs and colors |
| Hardware | CPU-first design for an 8 GB Apple Silicon machine |
| Execution | Manual commands; no scheduler or order placement |

Discovery will not use the portfolio or daily-report ticker list as its universe. Natural overlap is acceptable. Daily selections will change with the data, without forcing unnecessary ticker rotation.

## 2. Data collection and instrument selection

### Reuse the existing secure access layer

Reuse the existing credential loading, signing, bounded transport and safe error handling. Add only the documented screening and enrichment operations needed by this tool.

The current collector is useful reference material, but it is not a market-wide screener and its history-job limits do not accommodate this workflow unchanged. Build a separate orchestrator rather than silently expanding the reporting collector.

Moomoo documents REST screening with filtering, sorting and pagination, so an OpenD installation is not the default dependency. Actual endpoint coverage, units, permissions and quotas must be established during the first implementation epic. [Moomoo screening documentation](https://open.moomoo.com/zh-cn/api/quote/screening/stock-screen), [official API catalog](https://open.moomoo.com/mcp-docs/available-tools).

### Select the 100-name master

**Company stocks: target 80**

- Select 20 eligible winners, 20 eligible losers and 40 dollar-volume leaders.
- Deduplicate securities and share classes; retain all applicable selection reasons and ranks.
- Refill overlaps from the corresponding ranked pool.
- Default eligibility: price ≥ $5, median 20-session dollar turnover ≥ $25 million, and at least 252 valid daily sessions.
- Exclude OTC instruments, suspended securities, warrants, preferreds and unidentified product types.
- Cap a company-stock sector at 16 names; refill from other eligible sectors.
- Display profitability and financial-quality metrics where available. These describe quality; they do not establish future earning potential.

**ETFs: target 20**

- Target 12 ordinary long, four leveraged long and four inverse ETFs.
- Within leveraged long: target two 2x and two 3x products.
- Within inverse: target two −1x, one −2x and one −3x product.
- Select by liquidity and current activity within each bucket.
- Verify issuer, benchmark, signed leverage and reset period from attributable metadata.
- Cap two ETFs per benchmark family. Do not pretend long, inverse and leveraged versions of one index provide independent diversification.
- Report shortfalls rather than relaxing filters or forcing risky products into the list.

These are discovery quotas, not portfolio allocations. Leveraged/inverse ETF forecasts use the fund’s actual prices; they must not be generated by multiplying or reversing an index forecast. Daily reset and compounding make that shortcut unsuitable for multi-day forecasts. [SEC explanation](https://www.sec.gov/files/investor/pubs/leveragedetfs-alert.htm).

**Separate speculative panel: up to 10**

Use a disjoint, liquid pool with price ≥ $1 and median 20-session dollar turnover ≥ $5 million. Flag short history, low price, unusually large moves or high volatility. Never force-fill ten names. Insufficient history remains visible.

### Metrics in the master

Keep the master extensive while keeping the prediction feature set small.

| Group | Fields |
|---|---|
| Identity | Symbol, name, security ID, exchange, stock/ETF type, sector, industry |
| ETF exposure | Benchmark, issuer, signed leverage, inverse flag, reset period |
| Current observations | Latest quote and time, completed-session OHLC, volume, turnover, daily change |
| Popularity/liquidity | Winner/loser/volume ranks, dollar-volume rank, relative volume, median dollar turnover, spread when valid |
| Financial context | Market cap, EPS, P/E, revenue/profit growth and financial period where supported |
| Numerical features | Returns, ATR, volatility, moving-average distances, range position, benchmark-relative return |
| Events | Earnings, splits and distributions, including unavailable/unknown status |
| Native signals | Native bullish/bearish counts, timeframe, timestamp and capability status |
| Forecasts | Four low/high estimates, uncertainty bounds, terminal-return estimates and model status |
| Decision | Action, primary horizon, ranking score, reason, validation status |
| Provenance | Source, retrieval time, availability time, units, adjustment basis and run ID |

Unavailable native UI counts stay blank with a reason. Screener match totals and local indicator votes must never populate those columns. Separately named local signals may be displayed.

History collection will bootstrap new instruments, update missing completed sessions and retain revisions. Each run freezes its universe and data vintage. Unsupported fields remain unavailable rather than being silently inferred.

## 3. Numerical forecasting and research decisions

### Recommended model

Use **a transparent historical-excursion baseline plus nine small pooled quantile regressors**.

The baseline estimates historical low/high excursions scaled by origin-time volatility. The trained challenger uses scikit-learn’s histogram gradient boosting, which supports quantile loss. [Official estimator documentation](https://scikit-learn.org/stable/modules/generated/sklearn.ensemble.HistGradientBoostingRegressor.html).

The nine estimators cover three targets, each at the 5th, 50th and 95th percentiles:

1. Whole-period lowest low, relative to the reference close.
2. Whole-period highest high, relative to the reference close.
3. Terminal return, needed for directional screening.

Horizon, window lead time, session count, instrument class and leverage are features, allowing shared models instead of a separate model for every ticker.

Use shallow trees, sequential fitting, bounded CPU threads and explicit chronological validation. Start with a fixed small configuration; avoid an expensive tuning search.

Chronos-Bolt Tiny is a free, locally usable alternative worth benchmarking later. It supports numerical time-series forecasts, but ordinary closing-price forecasts do not directly satisfy this project’s whole-period intraday-extrema requirement. It is therefore outside the initial dependency set. [Official model card](https://huggingface.co/amazon/chronos-bolt-tiny).

### Minimal prediction features

Start with approximately 20 causal features:

- Returns over 1, 5 and 20 sessions.
- Overnight gap, daily range and close position within the range.
- ATR14/close and 20-session realized volatility.
- Distances from SMA20/SMA50 and trailing 20-session high/low.
- Relative volume and trailing dollar turnover.
- Broad-market relative returns and volatility.
- Instrument class, signed leverage, weekday and forecast-window information.

Financial metrics remain display/filter inputs initially. Do not train on today’s fundamentals pasted onto historical rows.

### Forecast definitions

Reference price is the latest usable completed-session close.

For each window:

- **Predicted low/high:** median estimates of the eventual minimum low and maximum high.
- **Uncertainty bounds:** separate outer quantiles, with measured coverage.
- **Next week:** trading sessions in the following calendar week in New York, excluding holidays; not simply the next five sessions.
- Include explicit reference, start and end dates.

Do not force a predicted range to include the reference close: a future period can gap entirely above or below it.

On-demand runs can occur at any time, but live quotes remain separate from daily-bar model inputs. A forecast whose window has already started is labeled accordingly and excluded from fresh-entry candidates.

### Training and saving

- Target three to five years of OHLCV, subject to actual availability.
- Accept a directory/glob of canonical historical CSV files.
- Also support read-only SQLite input through the same canonical OHLCV schema.
- Derive realized labels from later observed bars; **never train on the script’s own predicted-price columns**.
- Preserve all OHLC prices on a consistent split-adjustment basis.
- Split all instruments by date together; purge overlapping target windows.
- Save estimators, feature order, calendar, adjustment policy, training cutoff, calibration results, dependency versions and data hashes.
- Inference loads an existing trusted model; it never silently retrains.

Numeric forecasts are mandatory for instruments with sufficient valid inputs. Missing or inconsistent data produces an explicit unavailable result; the program will not invent numbers to fill the workbook.

### BUY/SELL and top 20

Use the three-session terminal-return forecast as the default decision horizon. All other forecasts remain visible.

- **BUY:** bullish candidate for buying that listed stock or ETF.
- **SELL:** bearish/avoid-new-long candidate; review an exit only if held.
- **WATCH:** weak, conflicting or insufficiently validated signal.
- **NO TRADE:** failed data or tradability checks.

Buying an inverse ETF is still a long purchase of that fund. Show its underlying exposure separately.

Freeze the initial directional threshold at the greater of 0.5% or twice the configured round-trip cost; use 1% for leveraged products. These are research defaults to evaluate, not established profitable rules.

Rank by cost-adjusted directional return relative to volatility, not by the width between predicted high and low. Produce up to 20 unique candidates, with caps of four stocks per sector, five ETFs overall, two leveraged/inverse ETFs, and two names per common exposure family. Do not force a BUY/SELL balance.

## 4. Scripts, outputs and example

### User-facing scripts

Provide four small entry points sharing one implementation:

```text
# All parameters have defaults; each script can run without arguments.
python scripts/stock-research/collect.py
python scripts/stock-research/train.py
python scripts/stock-research/predict.py
python scripts/stock-research/run.py

# Optional overrides; omitted parameters use configured defaults.
# Training defaults to the configured historical CSV directory.
# --sqlite selects SQLite instead; --table defaults to ohlcv.
# Prediction defaults to online mode; --offline disables provider and LLM calls.
python scripts/stock-research/collect.py --config config.toml
python scripts/stock-research/train.py --csv-dir /path/to/history --model-dir /path/to/models
python scripts/stock-research/train.py --sqlite /path/to/data.sqlite --table ohlcv --model-dir /path/to/models
python scripts/stock-research/predict.py --offline --state-dir /path/to/state --model-dir /path/to/models
python scripts/stock-research/run.py --config config.toml
```

`run.py` performs collection, cached-history updates, inference and export. Initial training is explicit. `--offline` prohibits provider and LLM calls.

The README will include installation, Moomoo credential references, first-run history bootstrap, training, everyday execution, offline replay, output meanings and common failures.

### Export bundle

CSV cannot retain worksheet tabs or cell colors. Deliver both CSV datasets and the workbook below.

At generation time, create a new `YYYY-MM-DD_HHMMSS/` folder under a configured parent directory such as `stock-research-data/`. Use one generation timestamp for the entire bundle and never overwrite an existing folder. Store all generated CSVs, XLSX workbooks and other artifacts, including manifests and trained-model artifacts, within that timestamped folder. Keep the parent directory outside the repository; if configured inside it, exclude the entire parent directory through `.gitignore` so its contents are never committed to GitHub.

- `master.csv`: one wide row per main instrument, containing all metrics and four forecast windows.
- `forecasts.csv`: machine-readable instrument/horizon rows.
- `top20.csv`, ranked winner/loser/volume views and one CSV per sector.
- `speculative.csv`: separate panel.
- Historical OHLCV CSVs suitable for training.
- `research.xlsx`: Summary, Master, Winners, Losers, Volume, sector tabs, ETFs, Speculative and Coverage.
- A run manifest containing selection rules, data/model versions, generation timestamp, artifact paths and failures.

Workbook actions use green BUY, red SELL, amber WATCH and gray NO TRADE, alongside text labels. Include filters, frozen identity columns and readable numeric formats.

Outputs and trained models stay in a configured local data directory outside Git. Only fictional examples belong in the repository.

### Optional sentiment

Default enrichment mode: `--sentiment auto`, with `--sentiment off` as an explicit opt-out. Auto attempts only configured, permitted enrichment and skips a failed connection, unavailable credential or quota. The numerical forecast remains price-only until a separately compatible sentiment model demonstrates the required out-of-sample benefit; checking a connection never authorizes silently changing model features.

Later support `cached`, supplied numeric JSON and explicitly configured API access. Convert attributable news into bounded numeric sentiment with timestamps, missingness and provenance.

Missing credentials, exhausted quota, timeout or malformed responses switch to the compatible price-only model. Missing sentiment is not neutral zero. A sentiment-trained model requires historical sentiment data and separate evaluation.

ChatGPT subscription access does not automatically provide API funding or credentials. The CLI will not scrape session tokens or depend on ChatGPT availability. [Official pricing distinction](https://learn.chatgpt.com/docs/pricing).

Acceptance must cover:

- **Data:** pagination, duplicates, incorrect units, missing OHLC, stale/future timestamps, splits, partial responses, quota failures and halted instruments.
- **Selection:** 100 combined names, deduplication, stock/ETF quotas, sector/exposure caps, speculative separation and honest shortfalls.
- **Forecasts:** a strong, empirically validated forecasting model is non-negotiable. Verify hand-calculated extrema fixtures, holidays, next-week boundaries, gaps above/below reference, crossing quantiles and incompatible models. Require leakage-free, purged walk-forward evaluation and an untouched chronological holdout across market regimes, with results reported by horizon and instrument/leverage class. Set quantitative acceptance thresholds before evaluation for endpoint errors, pinball loss, interval coverage and width; promote the trained model only when it demonstrates consistent out-of-sample improvement over the historical-excursion baseline without material calibration regressions. Failed gates block production-model acceptance; baseline fallback remains explicitly labeled research-only, not evidence that the strong-model requirement has been met.
- **Training:** date-based splits, label-window purging, identical CSV/SQLite interpretation and reproducible model reload.
- **Evaluation:** on each generation run, compare saved forecasts from previous runs with newly collected actual OHLC (open, high, low and close prices for a trading session) data once their full forecast windows have ended, even for instruments no longer in the current selection. Score the predicted whole-window low/high and terminal return against realized values, not against newer predictions; keep unfinished windows pending and flag missing actual data rather than scoring it. Preserve forecast dates, model versions and original predictions for auditability. Compare the model against baseline forecasts saved for the same instruments and windows using endpoint errors, pinball loss, interval coverage and width; export per-forecast scores and cumulative results separately by horizon and instrument/leverage class. This ongoing scoring does not automatically retrain or replace the model.
- **Resources:** measure peak memory ≤2 GB, training target ≤10 minutes and cached 110-name inference target ≤10 seconds on the actual machine. These are acceptance targets, not measured claims.
- **Exports:** numeric CSV values, consistent workbook contents, sortable actions, visible unavailable fields and verified formatting.
- **Sentiment (local-first, no LLM required): evaluate finance-specific lexicons and TF-IDF/linear classifiers before an optional small local financial sentiment model; no validated conversion skill is assumed. Validate against labeled financial news and leakage-free forecasting holdouts before using numeric sentiment in inference. Define score as P(positive) − P(negative), bounded to [−1, 1], with calibrated probabilities, ticker relevance, publication/first-seen timestamps, provenance and missingness; lexicon scores require separate calibration. Use only news available at the forecast cutoff, deduplicate syndicated articles and aggregate by ticker with time decay. Research free publisher RSS/Atom feeds and company investor-relations feeds first; compare coverage, latency, extraction permissions, historical availability and documented polling limits before choosing sources. Extract permitted article text, otherwise label headline-only analysis explicitly; do not bypass paywalls. Add a separate news collector with a default 5-minute interval and optional 1-minute polling only where permitted, conditional requests, shared caching, per-source request budgets, Retry-After handling and exponential backoff. No public source is assumed unlimited or immune to rate limiting; if permitted polling cannot meet the interval, use cached news and report staleness. Keep price-only inference as the default until historical sentiment and out-of-sample benefit are validated; unavailable sentiment is missing, not neutral zero. Optional remote LLM independence:** collection, training and prediction work with no LLM credentials; unavailable sentiment cannot break numerical forecasts.

A model that fails the evaluation gates remains a research model or falls back to the baseline. Numeric output, forecast accuracy and profitable trading are separate acceptance questions.
